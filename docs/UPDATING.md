# 更新与发布

## 使用者更新

1. 在旧网页点“导出参数”，把 JSON 保存好；原始图片也要保留。
2. 下载新 Release 的 `.tgz`，通过 DSH 插件管理安装/更新同名 bundle。
3. 按 DSH 提示重新加载或重启；再从原对话重新打开工作台。
4. 重新载入原图、导入参数包，抽查一张再批量输出。

不要把旧标签仍显示的页面当成新版。浏览器页面不热更新，重新打开才能加载新的渲染代码。插件不自动覆盖电影项目里历史的“资产光影匹配工具.html”。

若需回退，在 DSH 插件管理安装旧 Release 包。保留旧参数与原图；目前没有自动数据迁移或会话恢复。

## 维护者更新源码

在本仓库目录执行：

```powershell
git pull --ff-only
npm run check
npm test
npm pack --dry-run
npm pack
```

运行时零依赖，无需为此执行 `npm install`。Git 有本地修改时先保存自己的工作，避免用强制重置覆盖。`npm pack` 生成 `.tgz`，再用 DSH 安装该包。

改动网页时同步考虑 `window.assetColorMatch`、`bridge.js`、工具 schema 与参数包格式。修改像素算法必须保留/更新有依据的数值用例，并重验预览与原尺寸导出。不要为提高分数修改预期值来掩盖差异。

## 发布一个版本

1. 改 `package.json` 版本，写 `CHANGELOG.md`，更新验收记录。
2. 完成上述检查，再在目标 DSH 中安装包，实际验证默认浏览器打开、读图、填写、手调、输出。
3. 检查打包清单：只能含代码、文档、许可证与数值例子，不包含缓存、图片、输出、令牌或个人配置。
4. 提交代码，推送分支；给同一提交打版本标签，创建 GitHub Release 并上传 `.tgz`。
5. 包内容与 Git 标签一致。发布说明明确验收版本和仍未验证的范围。

本插件没有自动更新宿主、修改 `app.asar` 或强制重启 DSH 的步骤。DSH API 有变化时，以实际安装版本为准调整注册适配；不要靠修改宿主内部文件保持兼容。
