# 来源与设计记录

## 从电影创作需要出发

原始素材是《凌云渡》项目中用户提供的单文件“资产光影匹配工具.html”。已有参考图、资产队列、线性 Grade、自动统计匹配、预设、比较视图与 PNG 导出。该原型的更早作者及生成过程没有可验证的版本记录，本仓库不把未知经历写成原创声明。

本次扩展由用户提出需求、决定工作流和发布位置，Codex 协助实现、检查和编写说明。没有采用此前讨论的 GitHub 第三方颜色匹配项目，也没有引入它们的代码依赖。DSH 宿主接口参考本机安装的 DSH 及用户现有插件的注册方式。

项目经历的实际取舍：

1. 用户曾考虑插件、手填数值和 `.nk`。Nuke 渲染发生过崩溃；未对崩溃原因作完整诊断，不能把它归因于英文路径。
2. 最终用途明确为 AI 视频的参考图，保留角色、服装和构图特征，主要协调色调；不需要完整合成工程。
3. 用户要求以 Grade 为主，增加 Keyer 和 CC；由智能体看图填数值，自己在网页判断。
4. 决定做成 DSH 插件，用系统默认浏览器打开，用户可参与或跳过微调。
5. 用户明确不需要持续同步手调状态。插件只在命令执行时读取；输出复用网页渲染器，避免另做一套容易与预览不同的算法。
6. 独立公开仓库名由用户确定为 `zxw219/dsh-asset-color-match`。公开内容为代码、说明与数值示例，不包含电影资产图片。

## 借鉴合成师的哪些工作

| 合成工作中的判断 | 本工具的对应实现 |
|---|---|
| 看背景的亮度、冷暖、黑位和高光 | 参考图并排、采样区域；智能体实际读参考图 |
| 先让资产整体进入环境 | Grade 的 RGB 参数和强度 |
| 避免某一明暗/颜色范围被调整过多 | Keyer 生成渐变遮罩，按需限制 Grade / CC |
| 调整暗部、中间调、亮部的偏色 | CC 分段修正 |
| 对比原图、保护原始素材、输出版本 | 分屏/原图对比、参数包、同名自动编号 |

摄影与合成知识帮助选择合理参数，但仍要判断皮肤是否保留辨识度、衣料是否丢细节、参考图是否适合该镜头。一个全局 Grade 无法恢复原图没有的光照；亮度 Keyer 也无法准确区分等亮度的脸与衣服。

本工具没有 Nuke 节点图、跟踪、Roto、3D、深度合成、去溢色或完整 Keylight。这里的 Keyer 指颜色/明暗键控选区。界面使用熟悉的节点名帮助交流，不声称实现完整 Nuke。

## 算法与验证的边界

像素先从标准 sRGB 解码到 Linear，用浮点数执行 Grade / CC，最后编码、量化为 8-bit PNG。预览用缩小图片，最终输出对原图重算；预览与成品尺寸不同，缩放观感和细节可能不同。

保留在 `tests/legacy-web.cjs` 中的 Nuke 对照数值来自此前在本机 **Nuke 17.1v2** 的小样本检查：10 种 Keyer 操作的一组 RGB 输入，以及 CC 的 3 组像素输入。Grade 还检查了中性、负值、超白和 Gamma 边界。它们是有限的数值回归依据，不是全参数穷举，不证明整个 Foundry 色彩管理或所有节点功能等价。本仓库日常测试不启动 Nuke。

示例包只含此前用户确认的夏仁、凌小莹人物与服装 4 项参数，不含原图。它不是通用的“暴风雪正确答案”，不应按文件名盲目用于不同图片。
